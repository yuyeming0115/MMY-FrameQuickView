# M24 - 文件夹变更自动刷新

> 状态：开发中　|　分支：`feature-folder-watch`　|　日期：2026-08-29

## 需求背景

应用打开期间，用户在应用外对拖入的文件夹做了增删（美术工具持续导出帧、
删除部件、新增方向目录等），应用不会自动感知——必须手动重新拖入目录。

典型工作流：美术边导出边预览 → 导出软件写完一批帧 → 希望应用自动出现新帧。

## 设计方案

### 1. 监听机制（QFileSystemWatcher + 防抖）

- 新增独立 `_dir_watcher: QFileSystemWatcher`（与匹配表 watcher 分离）
- 扫描完成后递归收集 root 下全部子目录并 addPath（帧文件增删会触发
  所在动作目录的 `directoryChanged`；新增/删除子目录触发其父目录）
- **防抖**：`directoryChanged → QTimer(1000ms, singleShot) → 重扫`。
  美术批量导出会连发大量事件，静默 1s 后只重扫一次

### 2. 大目录降级（watch 上限保护）

- 递归收集的目录数 ≤ `WATCH_LIMIT`（2000）→ 全量监听（单套装约几百目录，常态）
- 超限（如 `角色输出图` 221 件 ≈ 万级目录）→ 只监听 root + 套装父目录 + 部件目录
  （部件级增删仍可感知；帧级变更降级为不感知，避免句柄耗尽）

### 3. 重扫状态恢复（不打断用户）

重扫 = 复用 `_on_folder_dropped(root)`，随后恢复现场：

| 状态 | 恢复策略 |
|------|----------|
| 当前选中项 | 记录 key（组 key / 部件路径），重扫后 `_select_by_key`；已删除则保持默认第一项 |
| 方向 / 动作 | 记录当前组合，重扫后 `_update_matrix(d, a)`；新数据缺失时由矩阵兜底逻辑接管 |
| B 区播放/暂停 | 之前在播 → 解码完成后自动播放（现有行为）；之前暂停 → 恢复暂停 + clamp 到有效帧 |
| 显隐 toggle | `_hidden_parts`（QSettings）自动恢复，现有行为 |

### 4. 开关与提示

- ⚙ ID 菜单新增 checkable「📡 自动刷新（外部变更）」，默认开，QSettings 记忆
- 自动刷新后状态栏提示「📡 检测到文件变更，已自动刷新」
- 拖入目录被删除（watcher 全部失效）→ 不重扫，等待用户重新拖入
