# M23 - 套装组跨 ID 整装预览

> 状态：已合并（PR #8 → main @32d8399）　|　分支：`feature-outfit-group`　|　日期：2026-08-29

## 需求背景

职业装（一套完整角色资源）由**多个不同资源 ID** 的部件组成（武器 ID、发型 ID、服装 ID），
美术会把这些部件放进一个父级文件夹统一管理：

```
hero\50151100_女主2_红拂女\Render_Output\501521005_女主2_女侠客(双刀)_部件\
    501031005_shadow    ← 武器 ID 的影子
    501031005_weapon    ← 武器 ID 的武器
    501511005_hair      ← 发型 ID
    501521005_body      ← 服装 ID 的主体
    501521005_shadow    ← 服装 ID 的影子
```

```
新ID\天命女(琴)\
    50141151_hair
    50142151_body
    50142151_shadow
```

现行为：按 res_id 分组 → 拆成 2~3 个 ID 组，无法整装叠层预览。
诉求：拖入这类父级文件夹时，**整套部件合并为一个「套装组」**，一次看全。

## 设计定稿（2026-08-29 与用户确认）

### 1. 检测规则（纯结构判定，不依赖命名后缀）

一个文件夹同时满足以下条件 → 其直接子部件合并为一个套装组：

- 直接子项含 **≥2 个叶子部件文件夹**（内层直接是 direction 的文件夹）
- 这些部件（按 folder_pattern 解析）**跨 ≥2 个资源 ID**
- 部件总数 **≤ `outfit_merge_max`（模板字段，默认 16）**
- **全部属于同一资源类别**（如全主角）——排除「翅膀+坐骑+主角」混放堆，
  也排除大库（`角色输出图` 跨 190+ ID 混多类别）；名字解析失败的部件不参与判定

超阈值或混类别 → 安全降级为现有按 ID 分组，行为不变。

配套调整：递归深度 max_depth 4 → 6（覆盖 `根\hero\角色\Render_Output\部件` 层级）。

### 2. 用户确认的交互决策

- **重名部件（双 shadow）默认全部显示**，与现有组视图一致；
  显隐 chips 用**归属名**区分：`武器影子` / `身体影子`（影子归属同 ID 主件，见下）
- **组头显示 = 文件夹名去掉 `_部件` 后缀**（如 `501521005_女主2_女侠客(双刀)`、`天命女(琴)`），
  带「套装」标记；ID 组头维持 `ID · 中文名` 风格
- **影子归属文案**（测试反馈优化）：影子部件的中文名 = 同 ID 主件中文名 + `影子`
  （`501031005_shadow` → 武器影子，`501521005_shadow` → 身体影子）；
  同 ID 无主件时兜底纯 `影子`；归属优先级 body > weapon > 其余
- **套装组子项显示 = `ID 中文`**（如 `501031005 武器影子`，ID 在前）；
  非 shadow 重名部件的显隐 chips 仍用 `中文·ID`

### 3. 数据模型（IdGroup 扩展）

| 字段 | 说明 |
|------|------|
| `key` | 组唯一键：ID 组 = res_id；套装组 = 父文件夹完整路径 |
| `is_outfit` | 是否套装组 |
| `display_name` | 套装组头显示名（ID 组为空，由 part_list 查匹配表拼） |
| `res_id` | 套装组 = **body 部件的 res_id**（缺 body 取首个非 shadow/fills 部件） |

左栏选择信号、红点刷新、app 组查找统一改用 `key`（res_id 会撞）。

### 4. 查漏与配套校验

- 角色类型 = body 部件的类型（匹配表/前缀推断链路同单部件）
- 方向×动作缺漏 = 组内全部部件**并集** 对照类型基准（与现组级一致）
- 配套校验（shadow 对不上主体）、fills 警告、多余动作 = 沿用并集规则

### 5. 叠层渲染

- layer_order 不变（shadow 最底 → body → hair → weapon…），跨 ID 各部件按各自 (方向,动作) 取帧合成
- A 区网格 / B 区动画均按叠层合成（复用现组视图管线，无需新渲染逻辑）
