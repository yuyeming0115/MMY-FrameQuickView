## 1. 需求背景与目标

主角采用**拆分模块化的时装搭配系统**，资源按部件（hair/body/weapon/shadow…）拆成独立文件夹；父目录中同时存在**纯 ID 文件夹**（如 `505026`，整体输出无部位拆分）。烘焙/导出后需要一个**极速**工具：

1. 拖入部件文件夹或父级目录，立刻看到全部序列帧 + 动画效果
2. 快速切换 部件 × 方向 × 动作，逐一检查
3. **查漏补缺**：缺方向、缺动作、帧号断档
4. **配套校验**：同 ID 部件叠层显示，确认 shadow/weapon 等与主体资源配套正确

## 2. 功能需求详述

| # | 需求 | 方案要点 |
|---|------|---------|
| F1 | 拖拽文件夹 → 显示序列帧 + GIF 动画 | 双显示区：A 区序列帧网格，B 区动画播放。拖入单个部件文件夹直接载入；拖入父级目录 → 左栏部件列表 |
| F2 | 部件/方向/动作快速切换 | 方向/动作**按钮全展开**；部件用**左栏可搜索列表**（按 ID 分组、过滤框、↑↓ 键、回车）。按钮/列表项带缺失标记 |
| F3 | 组合范围界定 | **不做**跨 ID 自由搭配组合；**同 ID 部件可叠层**（shadow 最底层，配套校验用） |
| F4 | 100% 原尺寸 + 包围盒裁剪 | 非破坏性裁切：动画用**全序列并集 bbox**（防抖动），网格单帧用自身 bbox；叠层各层共用同一并集 bbox 对齐；无边框、透明背景 |
| F5 | 规则模板模块 | JSON 模板：文件夹命名模式（部位后缀可选）、部位/方向/动作清单、层级顺序、**叠层顺序 layer_order**、帧命名规则 |
| F6 | B 区背景 | 默认透明融入 UI，可切换棋盘格底 |

### 3.2 左栏部件列表

- 拖入父级目录自动扫描一级子文件夹，符合模板规则（`{id}(_{part})?` 且内含方向文件夹）的列入
- **按 ID 分组**：组头 = 资源 ID；组内 = 该 ID 下各部位（缩进显示，部位后缀金色高亮）
- 顶部过滤框实时筛选；↑↓ 键移动、回车打开；有缺漏的项带 🔴 红点
- 拖入单个部件文件夹时列表只剩该项

### 3.3 同 ID 叠层（v0.3 新增）

- 选中某部件后，若同 ID 存在其他部件 → 按钮区下方出现**叠层 chips**，默认同 ID 全部勾选
- 叠放顺序按模板 `layer_order`，**shadow 固定最底层**
- A 区网格与 B 区动画均显示叠层合成效果；各层共用同一并集 bbox 窗口对齐
- 用途：检查资源是否配套正确（shadow 是否对得上武器/身体动作）

### 3.4 其余交互

- **方向/动作按钮**：模板全量展开；选中=金色描边；缺失=暗红底
- **A 区**：横向排满自动换行；帧号标注；点击帧 → B 区跳转
- **B 区**：播放/暂停、FPS 滑杆（1–60）、逐帧步进、循环模式；**背景 toggle：透明 / 棋盘格**
- **状态栏**：帧数、原尺寸 → 裁剪尺寸、帧号连续性、缺漏摘要
- **字号**：正文 ≥ 14px（视力适配）

### 3.5 视觉规范

深色主题：`#1E2023` 背景 / `#2A2E33` 卡片 / `#D4AF37` 金色强调 / `#C74444` 缺失警告。缩略图无边框、透明底融入卡片底色。

## 4. 规则模板系统设计（v0.3 定稿）

```json
{
  "name": "天命装",
  "folder_pattern": "{id}(_{part})?",
  "parts": ["hair", "body", "weapon", "wings", "ride_front", "ride_back", "shadow", "fills"],
  "directions": ["E", "N", "NW", "S", "SE"],
  "actions": ["idle", "run", "attack", "skill", "hurt", "block", "dead", "ride_idle", "ride_run"],
  "hierarchy": ["direction", "action"],
  "layer_order": ["shadow", "ride_back", "body", "hair", "weapon", "wings", "ride_front", "fills"],
  "frame_pattern": "^(\\d{4})\\.png$",
  "extensions": [".png", ".webp"]
}
```

| 字段 | 说明 |
|------|------|
| `folder_pattern` | `{id}(_{part})?` —— 部位后缀可选；纯 ID（`505026`）视为整体资源 |
| `hierarchy` | 默认 `["direction","action"]`；可反转 |
| `layer_order` | **v0.3 新增**：同 ID 叠层顺序，数组前 = 越底层；shadow 必须为首 |
| `frame_pattern` | 帧号提取正则；断档检测依据 |

模板管理：`templates/*.json` 启动自动扫描；顶栏切换 + 表单化编辑器；随 exe 打包并支持 exe 旁目录覆盖。

## 5. 技术方案（已确认）

**PySide6 + Pillow + numpy**，Python 3.13（WorkBuddy managed，绕开已损坏的系统 Python 3.14）。

| 层 | 选型 |
|----|------|
| GUI | PySide6（拖拽、按钮矩阵、左栏分组列表、双显示区、叠层 chips） |
| 图像 | Pillow 解码 + numpy alpha 包围盒；叠层用 QPainter 按 layer_order 合成 |
| 动画 | QTimer 逐帧驱动，FPS 精确控制 |
| 打包 | PyInstaller `--onefile --windowed` |

## 6. 核心算法要点

### 6.1 包围盒裁剪（非破坏性）

```
对每个动作序列:
  1. 逐帧读 alpha → 单帧 bbox
  2. 动画显示: 全序列 bbox 并集 → 统一裁剪窗口（帧间不抖动）
  3. 网格显示: 各帧自身 bbox
  4. 叠层: 参与层共享同一并集 bbox 窗口（对齐基准）
  5. 原文件不修改，裁剪只在内存/QPixmap 层发生
```

### 6.2 缺漏检测

- **结构层**：模板 方向×动作 笛卡尔积 vs 实际目录 → 按钮暗红 + 列表红点
- **帧号层**：动作内 min→max 区间连续即可（**不**要求从 0001 开始，实测跨动作连续编号）；
  可选增强：同方向各动作首尾拼接查整体缺段
- **配套层（v0.3）**：同 ID 各部件的方向×动作矩阵做**交集对比**，主体有的动作 shadow 缺 → 标记配套异常
- **汇总**：状态栏 + 可选导出清单

### 6.3 性能

- 扫描只读文件名（毫秒级）；图像惰性解码 + 工作线程 + LRU 缓存
- 大序列先显示网格骨架再逐批填充
