# M1 骨架模块 开发文档

> 分支：`feature-m1-skeleton` · 依据：01-需求方案与UI设计-v0.3.md

## 范围

拖拽 + 模板加载 + 左栏分组部件列表 + 方向/动作按钮矩阵 + 缺漏标记 + 状态栏汇总。
A/B 区为占位（M2 网格渲染、M3 动画播放接入）。

## 关键决策

1. **帧号检测规则**：实测 idle=0001–0008、attack=0017–0024 跨动作连续 → `ActionData.gaps` 只查区间内断档。
2. **层级转置**：scanner 内部统一为 direction→action 矩阵；模板 hierarchy 反转时扫描后转置。
3. **配套校验**：同 ID 组内取 方向×动作 并集为参照，任一部件缺则报「配套异常」（shadow 对不上主体会被标出）。
4. **入口兼容**：`src/main.py` 同时支持 `python -m src.main` 与 PyInstaller 直接打包。
5. **中文名映射**：沿用用户手写 txt（TAB 分隔），免维护四件套——自动发现（**从拖入目录向上递归到盘根**找 `*匹配表*.txt`，任意子层级拖入都能命中）/自动登记/内联改名回写/热更新（外部编辑自动刷新左栏，watcher 重挂防原子保存丢失监听）；**M7 增**：`QSettings("MMY","FrameQuickView")` 持久化 `last_map_file` 到 HKCU\\Software\\MMY\\FrameQuickView，下次启动/任意目录拖入兜底加载（解决了「拖 `E:\Temp\新ID` 这种无父级匹配表的目录也认中文」的诉求）；顶栏「文件」菜单含「重新加载匹配表」「选择匹配表文件…」做手动兜底。实测扫描真实目录自动登记 13 个新 ID。
6. **分方向动作约定（🔴 基准）**：角色类型判定链路（2026-08-29 补全）：**① 匹配表纯 ID 行第3列显式标注**（`template.CHAR_TYPE_ALIASES` 归一化：主角/hero→protagonist；伙伴/怪物/boss→non_protagonist；npc→npc；坐骑→mount；翅膀→wings）→ **② 未标注时按模板 categories 的 `char_type` 字段推断**（`Template.infer_char_type`，有序匹配：part_any 优先于 id_prefix；如 501 前缀→protagonist、ride_* 部件→mount）→ **③ 仍未命中→`default_character_type=non_protagonist`**。实测匹配表 310 行均无第3列，此前全部落入 ③ 导致主角 ride 动作永远灰显——② 即为此修的兜底。NPC 分类**故意不配 char_type**：保留「default 类型且无战斗/坐骑动作→npc」的行为兜底，比 505 前缀一刀切更准（避免带攻击动作的 505 资源 attack 被灰显）。`action_rules`(类型→方向→应含动作) 基准：
   - **protagonist**：E/N/S → idle,attack,run,ride_idle,ride_run；NW/SE → idle,run,attack,skill,hurt,block,dead,ride_idle,ride_run（ride_idle/ride_run 为全向动作，仅主角与坐骑出现，2026-08-29 修正：原基准漏了 E/N/S 的坐骑动作，导致主角切到 E/N/S 时 ride 按钮灰显）
   - **non_protagonist（伙伴/怪物/boss）**：E/N/S → idle,run；NW/SE → idle,run,attack,skill,hurt,block,dead
   - **npc**：全方向仅 idle,run
   - **wings（翅膀）**：全方向仅 idle,run（无 attack/skill/hurt/block/dead）
   - **mount（坐骑）**：全方向仅 ride_idle,ride_run（无 idle/run/attack/skill/hurt/block/dead）
   - 缺动作按「角色类型×方向」基准逐方向比对；按钮矩阵三态：缺=红 / 该类型不需=灰(disabled 感) / 正常=普通。红点=缺方向/缺动作/帧断档/配套异常任一。
7. **整体资源结构检测兜底（M15）**：`parse_folder_name` 只认 `{id}_{part}` 和纯 ID（字母数字），新工程命名 `{id}_{中文名}`（如 `503026_神龙`）会被漏掉。scanner 层加 `_looks_like_part_folder`：子目录含 ≥2 个已知 direction/action 即视为整体资源（part=None，res_id 取文件夹名数字前缀）。分类文件夹（如 `504004_黑龙王`，子目录是 `Render_Output`）不命中，继续下钻。`scan_part` 和 `_find_part_folders` 统一走 `_parse_folder_or_struct`。
8. **左栏右键复制（M16）**：左栏 ID 列表支持右键菜单复制到剪贴板——组头/子项均提供「复制 ID」「复制 ID · 中文名」（有中文名时）；子项额外提供「复制文件夹路径」。菜单样式沿用深色主题（选中态金色）。
9. **多余动作检测（M17）**：旧工程可能含模板外动作（如 catch/sprint）。scan_part 原先只遍历 tpl.actions 内的子目录，模板外动作被完全忽略。现改为遍历各方向实际子目录，不在 tpl.actions 但有有效帧的记入 `extra_actions: dict[direction, list[action]]`。PartData 和 IdGroup 均新增此字段（组级 = 组内并集），`has_issues` 纳入判定（左栏红点也会标）。状态栏显示 `⚠ 多余动作 E: catch, sprint`。
10. **ID壳四层结构（M18）**：`_find_part_folders` 原以「名字命中（_parse_folder_or_struct）」判部件文件夹。对四层结构 `怪物/503006/503006_body/...`，ID壳 `503006` 名字是纯 ID 会被误认作部件文件夹收集且不下钻，`scan_part(503006)` 找 direction 层失败 → 全部 ignored。改用新增的 `_is_leaf_part_folder`（直接子目录含 ≥1 个 direction）判叶子部件文件夹；非叶子（ID壳/分类/READM目录）继续下钻。名字解析仍由 scan_part 内的 `_parse_folder_or_struct` 负责。实测 `怪物` 目录 145 部件 / 51 组全识别，M15/M11 无回归。
11. **fills 警告级缺失（M19）**：旧工程常缺 fills 填充部件，原与 shadow 同归「配套部件」完全跳过查漏。现 fills 参与查漏，但作为**警告级（橙色）**：`scan_part` 对 fills 按「角色类型×方向」基准计算缺失，写入 PartData 新增 `warning_directions`/`warning_actions`（不进红色 `missing_*`，不打红按钮矩阵）。组级 `_group_parts`：组内存在主体部件但整组无 fills → IdGroup 新增 `missing_fills`（缺的方向）；有 fills 时合并其警告到 `fills_warning_directions`/`fills_warning_actions`。PartData/IdGroup 均加 `has_warnings` 属性。左栏组头/子项用橙色点 🟠（优先红 🔴），状态栏加 `🟠 缺 fills 部件（E,N,...）` / `fills 缺方向` / `fills 缺动作`。
