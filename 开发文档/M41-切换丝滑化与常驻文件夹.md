# M41：切换丝滑化 + 快捷文件夹「📌 常驻」

> 分支 `feature-m41-smooth-switch-and-pin-folders` · 2026-10-23
> 涉及模块：A 区网格（M2/M6）、快捷文件夹 chips（M30/M31）

## 一、需求

1. **左侧列表切换角色时，A 区序列帧网格会有一瞬间跳动**，不丝滑，影响体验。
2. **顶部快捷文件夹需要「固定 / 常驻」能力**：经常用的文件夹不能被新的历史记录冲掉。

## 二、问题定位（实测，非猜测）

用真实资源目录（`E:\XYJProject\美术资源\动画序列帧\角色输出图`，267 组）在 offscreen 下
逐次切换左栏组，插桩记录 A 区宽度、`_build_cells` 调用次数、调用栈：

```
[501031001] build=2 clear=3 resize=1 sizes=[(496, 837)]
[501031003] build=3 clear=4 resize=2 sizes=[(441, 837), (496, 837)]
[501031005] build=3 clear=4 resize=2 sizes=[(441, 837), (496, 837)]
```

三条硬结论：

1. **A 区宽度在 441↔496 之间反复跳 55px**。根因是「自适应」模式下格子尺寸由视口宽度反推，
   而 `FlowLayout.minimumSize()` 取的是格子尺寸 → `grid_view.minimumSizeHint()` 变成
   262↔496 浮动 → 横向 `QSplitter`（A|B）每次切换都按新的最小尺寸重新分配宽度。
2. **每次切换重建 2~3 次格子控件**：`_on_done` 建一次，宽度变化引发的 `resizeEvent`
   又各建一次，每次都销毁+新建全部 `_FrameCell`（8 帧 × 多层合成），中间态被画出来就是「跳」。
3. 旧解码线程 `quit()+wait()`（`run()` 无事件循环，`quit` 无效）→ 快速连点左栏时
   **主线程被上一轮解码卡住**，切换手感发涩。

## 三、方案

### 3.1 锁定 A 区最小宽度（根治宽度跳动）

`GridView.__init__` 里 `setMinimumWidth(240)`：给 splitter 一个显式下限后，
`minimumSizeHint` 的浮动不再参与横向分配，A 区宽度恒定（实测 387/441/736 均不再变），
用户在 splitter 上手动拖出的比例也不会被后续切换冲掉。

### 3.2 重建合并 + 就地刷新（消除重复重建）

- `_build_cells(force=False)`：
  - 布局签名 `sig = (模式, 帧数, 原图最大宽高, 视口宽, 视口高)`；
  - `force=True`（新序列解码完成 / 切原图↔自适应）必重建；
  - 签名未变 → `_refresh_cells_in_place()`：只把新 pixmap / 帧名换进现有 cell，**控件不动**；
  - `_building` 标志挡掉重建过程中再次触发的 resize 递归。
- `resizeEvent` → 40ms 单发 `QTimer` 合并连续 resize（滚动条抖动不再连环重建）。
- 重建期间 `viewport.setUpdatesEnabled(False)`，避免中间态闪现。

### 3.3 切换淡入过渡（视觉上「溶解」而非「跳变」）

`_on_done` 在换内容前 `self._scroll.grab()` 拍旧画面快照 → 新内容就位后在其上盖一层
`QLabel` + `QGraphicsOpacityEffect`，150ms `OutCubic` 淡出（`WA_TransparentForMouseEvents`
不挡交互，动画结束即销毁）。帧数/尺寸变化再大也不会看到「整块突变」。

### 3.4 解码线程可中断

`DecodeWorker.run()` 在 bbox 预计算循环与逐帧合成循环里检查 `isInterruptionRequested()`；
`GridView._stop_worker()` / `AnimView._stop_worker()` 改为
`requestInterruption()` → `wait()`。切走即放弃，不再等旧序列跑完。

### 3.5 快捷文件夹「📌 常驻」

原 M30 已有「右键 chip → ★ 固定为收藏」，但**只能右键发现**，且收藏上限 8 个会被新收藏淘汰。
本次升级为一级功能：

| 入口 | 行为 |
|------|------|
| 顶栏「📌 常驻」按钮（拖拽区右侧） | 一键常驻/取消常驻**当前目录**；常驻时金底深字；未加载目录时灰显禁用 |
| chip 右键菜单 | 「📌 设为常驻（不被新历史挤掉）」/「📌 取消常驻」/「🗑 从列表移除」 |
| chip 外观 | 常驻 chip = `📌` 前缀 + 金边金字，恒排最前；当前浏览中的 chip 仍用激活态（金底） |

规则：

- 常驻项**不占「最近」名额**，永不参与淘汰；`QUICK_RECENT_MAX=5` 只作用于历史记录。
- 常驻上限 `QUICK_PIN_MAX=30`，**只挡新增、绝不自动挤掉已有常驻**（超限时状态栏提示）。
- 取消常驻 → 回到「最近」最前；「从列表移除」→ 常驻 + 最近同时删除。
- QSettings 键由 `folders/favs`（旧收藏）迁移为 `folders/pins`，**旧数据自动继承**；
  读取用 `contains()` 判断（`type=list` 时缺失键返回 `[]` 而非 `None`，用 `is None` 判断会漏迁移）。

### 坑点记录

1. **`FlowLayout.minimumSize` 会往上污染布局**：滚动内容区的布局最小尺寸若随内容变化，
   会通过 `minimumSizeHint` 传导到 `QSplitter`，造成上层分区反复重排。给分区显式
   `setMinimumWidth` 是成本最低的止血方式（比改 FlowLayout 语义安全，原图模式的
   横向滚动条行为不受影响）。
2. **`QSettings(org, app)` 在本机 PySide6 下总是落注册表**（即使
   `setDefaultFormat(IniFormat)` + `setPath`），测试里直接 `S().clear()` 会清掉用户真实配置。
   测试统一把 `src.app.QSettings` 重定向到临时 ini。
3. **临时 ini 不能放在被扫描目录内**：应用每次切换会写 `last/selection`，会触发
   `QFileSystemWatcher` → 1s 防抖重扫 → 再写设置 → 重扫风暴（实测一次切换 29 次
   `_show_grid`）。测试 ini 一律放扫描目录之外。
4. `value(key, None, type=list)` 对缺失键返回 `[]` 而不是 `None` → 迁移判断必须用 `contains()`。
