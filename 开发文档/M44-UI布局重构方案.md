## 一、背景：为什么要重排

M1–M43 一路叠加功能，功能本身扎实，但**布局从 v0.3 定稿后没有重新排过**。
现在控件的位置反映的是「功能是哪个里程碑加进来的」，而不是「检查一个资源时眼睛和手怎么走」。

### 1.1 第一性原理：工具的本职

工具的核心是一个质检循环：

```
选资源 → 看全不全（缺方向/缺动作/断档/空帧/多余） → 逐个 方向×动作 看动画对不对 → 发现问题就定位
```

按操作频率分级（布局判断的唯一标准：**越常用越放眼前、越大、越近；不常用的收起来**）：

| 频率 | 操作 |
|------|------|
| 极高 | 切方向、切动作、看动画 |
| 高 | 切资源、看有没有问题 |
| 中 | 暂停逐帧、调 FPS、显示层开关、穿戴 |
| 低 | 换目录、换模板 |
| 极低 | 编辑/新建模板、匹配表、自动刷新、fills 检测 |

### 1.2 现状诊断

以 `角色输出图_版署` / `503122 · 宝箱怪`（SE · idle）实测截图为准：

**① 查漏补缺缺少「总览」**
方向×动作是 5×9 的二维关系，现在拆成两列一维按钮 + 角标数字。想知道全貌，
要么逐个点 5 个方向，要么悬停 HUD 展开。HUD 里的「方向-动作帧数账目」才是总览，但被藏起来了。

**② A 区几乎失效**
A 区约 290px 宽，8 帧缩略图每张只剩约 20px。原因：M39 起画布对齐默认开（`display/canvas_align = True`），
每帧都是完整渲染画布；「自适应」再把整张画布缩进格子，角色就变成一个点。

**③ 视线来回跑**
一次检查的视线路径：左栏 → A 区 → 夹在中间的按钮列 → 画布 → 底部控制条 → 右下 HUD → 左下状态栏。
按钮列（M35 改成独立列）插在 A、B 之间，把本该挨着的两个视图隔开了。

**④ 信息重复、开关分散**
- 「8 帧」同时出现在 A 标题、B 标题、HUD、状态栏、动作角标，共 5 处。
- 9 个开关散在 5 个位置：

| 位置 | 开关 |
|------|------|
| 顶栏 | 🟠 fills 检测、📐 画布对齐 |
| ⚙ ID 菜单 | 📡 自动刷新 |
| A 区标题 | 原图 / 自适应 |
| 方向列 | 显向 |
| B 区底栏 | 循环、棋盘格、📊 HUD、☰ 显示层 |

- fills 检测本质是一条「检查规则」（BOSS/主角本来就没有 fills），不应是全局视图开关。

**⑤ 细节问题**

| 问题 | 代码位置 / 原因 |
|------|----------------|
| FPS 滑杆被挤成一个点 | `anim_view.py` 只 `setMaximumWidth(120)`，没设最小宽度 |
| A 区按钮显示「点了会变成什么」，其他按钮显示「当前状态」，逻辑相反 | `grid_view._on_mode_toggled`：选中自适应时文字是「原图」 |
| 字号低于规范 ≥14px | `anim_view` 用 11/12px，`button_matrix` 11/12px，`part_list` 12/13px，`grid_view` 12px |
| 单部件资源状态栏写「1 层叠合 · shadow 最底」 | `app._refresh_status` 对组视图不区分层数 |
| 画布不能缩放，小怪看不清细节 | 无 `wheelEvent` / zoom 实现 |
| 快捷键只有方向键 | 无空格播放、逐帧键；无 `QShortcut` |
| 顶部虚线拖拽框长期占大块位置 | 整窗本来就支持拖入（`central.setAcceptDrops(True)`） |
| 样式分散 | 约 50 处内联 `setStyleSheet`，改主题/字号要逐个找 |

## 三、各区域规格

### 3.1 顶栏（只保留「在哪个目录 / 用哪套规则」）

- 当前目录做成可点的下拉（📁 名称 ▾）：下拉内容 = 常驻 + 最近目录（复用 M30/M41 数据）、「打开文件夹…」。
- 快捷目录 chips 保留在同一行，空间不够时折叠进下拉。
- 右侧：`规则模板 [下拉]` + `⚙` 设置菜单。
- **拖拽框只在「未加载任何目录」的空状态下大面积显示**；加载后整窗拖入（已有能力）+ 拖入时全窗口高亮提示。
- ⚙ 菜单收纳：编辑模板 / 新建模板 / 重新加载匹配表 / 选择匹配表文件 / 自动刷新 / 检查规则（fills）/ 显向热区开关。

### 3.2 左栏：资源列表

- 保留：过滤框、分类 chips（M21）、按 ID 分组、F2 改名、右键菜单（M43 清理入口）。
- 新增「全部 N / 有问题 N」筛选（分段按钮），只看有红点/橙点的项。
- 每行右侧显示总帧数（等宽字体、次要色），一眼看出谁明显少帧。
- 单部件资源（组内只有 1 个部件）**不显示展开箭头**，减少无意义层级。
- 底部「共 N 项」计数移到状态栏。

### 3.3 中栏：舞台 + 时间轴（主角）

**舞台标题行**（替代 A/B 两个标题 + 状态栏的当前项信息）：
`资源名 · 方向·动作 · N 帧 起–止 · 帧号连续/⚠缺帧`，右侧放两个只影响舞台的切换：
- `[画布对齐 | 内容裁剪]`（原顶栏 📐 画布对齐，改为分段按钮，状态一目了然）
- `[透明 | 棋盘格]`（原底栏「棋盘格」复选框）

**舞台画布**（原 B 区 `_AnimCanvas`）：
- 新增缩放：`适应 / 1× / 2× / 4×` + Ctrl+滚轮；1×、2× 用最近邻插值（像素艺术不糊）。
- 新增可选地面基准线 + 原点十字（检查各方向落脚点是否一致；画布对齐模式下才有意义）。
- 保留 3×3 显向热区（M8/M35）；显示层面板、HUD **不再浮在画布上**。
- 空帧提示（M36）保留在画布中央。

**时间轴**：
- 控制行：`⏸/▶`、`◀ ▶`、`帧 3/8`、FPS 滑杆（**最小宽 120px**）+ 数值、`循环`、右侧 `[胶片条 | 整页网格]`。
- **胶片条**（A 区改造，默认）：一行横向排列全部帧，横向滚动；当前帧金框；缺帧位置画红色空槽；空帧格标红；
  点击跳帧；右键沿用 M40「复制原图」。
- **缩略图固定用内容裁剪（各帧自身 bbox 或并集 bbox）**，不受画布对齐影响 → 解决「缩成一个点」。
- 「整页网格」= 原 A 区网格模式，切换后占满舞台区域（舞台暂时让位），再点切回。

### 3.4 右栏：检查器

从上到下四个可折叠区块，超高时整列滚动：

**① 方向 × 动作矩阵**（替代方向/动作两列按钮 + HUD 主体）
- 列 = 模板 `directions`，行 = 模板 `actions`；每格显示帧数。
- 格子状态（沿用现有语义与配色）：

| 状态 | 样式 | 数据来源（现有） |
|------|------|----------------|
| 有资源 | 卡片底 + 帧数 | `ActionData.count` |
| 当前 | 金色 2px 边框 + 金字；当前列/行轻微金色底 | `matrix.current()` |
| 缺失（规则要求但没有） | 暗红底 `#C74444` | `missing_actions` / `missing_directions` |
| 空帧（全透明占位） | 暗红底 + 「空」 | M36 `_blank_cache` |
| 帧号断档 | 帧数后加 ⚠ | `ActionData.continuous` |
| 多余动作 | 琥珀边 + 「多」 | M43 `extra_actions` |
| 不适用 | 虚线框、灰点 | 模板 `action_rules`（如 worldboss 非 SE） |
| 部件帧数不一致（组） | 帧数后加 ⚠，悬停显示各部件帧数 | M32 HUD `ComboStat` |

- 点击格子 = 同时切方向+动作；方向键 ←→ 切列、↑↓ 切行（**现有 M5 键位不变**，正好对应矩阵的横竖）。
- 表头点击 = 只切方向/动作；右键格子 = M43 清理菜单。
- 特殊结构：扁平特效（M21）= 单列「特效」；worldboss（M36.1）= 只有 SE 列可用，其余列灰显；
  方向数 >6 的模板自动缩小格宽。
- 矩阵上方显示「合计 N 帧」（原 HUD 合计）。

**② 显示层 / 穿戴**（原画布右上悬浮的 `PartToggles`）
- 部件显隐列表 + 穿戴特效/翅膀/时装/头发/武器下拉，逻辑完全复用，只是挪进右栏。
- 单部件资源显示「单部件资源，无叠层与穿戴项」一行说明，不再出现孤零零的「整体」按钮。

**③ 检查结果**
- 把状态栏里拼成一长串的 `⚠ 缺方向 / 缺动作 / 多余动作 / 配套 / fills` 拆成**逐条列表**；
  每条可点击 → 矩阵跳到对应格子。
- 全部通过时显示 ✓ 清单（无缺方向/缺动作、帧号连续、无空帧、无多余动作）。

**④ 资源信息**
- 部件数、原画布尺寸、内容 bbox 尺寸、文件夹路径（可点击打开资源管理器）。

### 3.5 状态栏

只放**全局信息 + 一次性提示**：`N 组资源 · N 组有问题 · 自动刷新 开/关`，右侧显示临时消息（复制成功、清理完成等）。
当前项的详情全部移到舞台标题行和检查结果。

## 六、代码结构调整（为重排扫清障碍）

### 6.1 新的 UI 文件划分

| 新文件 | 来源 | 职责 |
|--------|------|------|
| `src/ui/top_bar.py` | `drop_zone.py` 拆分 | 目录下拉、快捷 chips、模板下拉、⚙ 菜单 |
| `src/ui/empty_state.py` | `drop_zone.py` 拆分 | 未加载时的大拖拽区 |
| `src/ui/stage_view.py` | `anim_view.py` 的 `_AnimCanvas` + 播放逻辑 | 舞台画布、缩放、基准线、显向热区 |
| `src/ui/timeline.py` | `anim_view.py` 底栏 + `grid_view.py` | 控制行、胶片条、整页网格 |
| `src/ui/inspector.py` | 新增 | 右栏容器（可折叠区块） |
| `src/ui/ad_matrix.py` | `button_matrix.py` 改造 | 方向×动作矩阵（复用现有角标计算逻辑） |
| `src/ui/layer_panel.py` | `anim_view.py` 的 `PartToggles` | 显示层 / 穿戴 |
| `src/ui/theme.py` + `theme.qss` | 收拢约 50 处内联样式 | 统一配色、字号（≥14px 起步） |

`button_matrix.py` 里 `_part_badges` / `_group_badges` / `_dir_badges` / `pick_default_action` 的计算逻辑**原样保留**，
只把「输出到两列按钮」改成「输出到矩阵格子」，降低回归风险。

### 6.2 统一的检查结果来源

新增 `src/core/issues.py`：把 `app._refresh_status` / `_warnings_text` 里拼字符串的逻辑改成产出结构化列表：

```python
# 示意：每一条问题都是一个对象，界面各处只负责「怎么显示」
@dataclass
class Issue:
    level: str          # "error"（红）/ "warn"（橙）/ "extra"（琥珀）
    kind: str           # "missing_dir" / "missing_action" / "gap" / "blank" / "extra" / "pairing" / "fills"
    direction: str | None
    action: str | None
    text: str           # 给人看的一句话
```

矩阵格子颜色、检查结果列表、左栏红点、状态栏「N 组有问题」都从同一份 `Issue` 列表取数，不会再出现各处说法不一致。

### 6.3 统一视图状态

新增 `ViewState`（当前资源 key、方向、动作、帧号、播放态、各显示开关），由它负责读写 QSettings。
M29（恢复选中）、M33（切换保持方向动作）、M24（自动刷新保持现场）这类「切换后状态丢失」问题，根子在状态散在
`MainWindow` 和各控件里；集中后这三处逻辑可以合并。

### 6.4 穿戴逻辑去重

`app.py`（1695 行）里特效/翅膀/时装/头发/武器有 5 套几乎相同的 `_load_ / _save_ / _append_ / _on_xxx_dressed`。
抽成一个 `WearSlot` 类（槽位名、资源库、QSettings 键、当前选择、自动推断规则），`app.py` 只保留 5 个实例。

## 七、分阶段实施

## 八、风险与注意

- **QScrollArea sizeHint 塌缩**（M35.1 教训）：右栏检查器、胶片条都含滚动区，容器高度必须由布局直接拉伸，不能用对齐参数。
- **切换跳动**（M41 教训）：胶片条/网格重建要沿用 `_build_sig` 签名比对 + 原地刷新，避免 splitter 抖动。
- **最小窗口 1280×800**：左 240 + 右 286 后舞台约 730px 宽，够用；窗口更窄时右栏可折叠为图标条。
- **套装组层数多**（最多 16 层 + 5 个穿戴下拉）：右栏整列滚动，「显示层」区块默认展开、「资源信息」默认折叠。
- **习惯迁移**：方向键键位不变；首次启动新版弹一次「布局已更新」提示（可关闭，QSettings 记忆）。
