# M21 - 分类过滤与特效资源模块

> 状态：已合并（PR #7 → main @31ccd33）　|　分支：`feature/category-filter-fx`　|　日期：2026-08-28

## 1. 需求背景

1. **列表太长找资源不便**：拖入父级目录后左栏有上百个 ID 组，需要按资源类型
   （主角/伙伴/怪物/BOSS/NPC/坐骑/翅膀/特效）快速过滤。
2. **特效资源无法预览**：新增的特效资源（如 `50105101「环绕」游龙`）结构与常规资源
   完全不同——**无方向/动作子目录**，图片直接放在根目录，命名为
   `changrao_1.png ~ changrao_20.png`（前缀_序号，非四位补零），当前 scanner
   会因「无有效结构」忽略整个文件夹。

## 2. 分类规则设计（依据匹配表实测）

分类**不需要手工维护**，按「部件特征 → ID 前缀」有序匹配（顺序即优先级）：

| 顺序 | 分类 | 判定依据 | 说明 |
|------|------|----------|------|
| 1 | 坐骑 | 部件含 `ride_front`/`ride_back` | 比 ID 前缀稳：50401201 坐骑在 504 BOSS 段内 |
| 2 | 翅膀 | 部件含 `wings` | 50104101 在 501 主角段内，靠部件判定 |
| 3 | 特效 | ID 前缀 `50105` + 扁平结构 | 50105101 |
| 4 | 主角 | ID 前缀 `501` | 时装/发型/武器/神兵（含 9 位职业装 501121001） |
| 5 | 伙伴 | ID 前缀 `502` | |
| 6 | 怪物 | ID 前缀 `503` | 含 7 位五行变种（5030421 石骨飞鱼·金） |
| 7 | BOSS | ID 前缀 `504` | |
| 8 | NPC | ID 前缀 `505` | 剧情NPC |

分类判定在 **IdGroup 级别**（同 ID 部件组共享分类），规则存模板 JSON，换项目改模板即可。

## 3. UI 设计

### 3.1 分类 chips 行（左栏过滤框正下方）

```
┌─────────────────────────────┐
│ 🔍 过滤部件 / 中文名…   [▶][📖] │
│ [全部][主角][伙伴][怪物][BOSS]   │  ← 流式换行 chips
│ [NPC][坐骑][翅膀][特效]         │
│ ▸ 50105101 · 「环绕」游龙       │
│ ▸ 502001 · 陈靖仇        🔴    │
│ …                            │
└─────────────────────────────┘
```

- chips 为 checkable 小按钮，选中金色高亮（与叠层 chips 风格统一）
- 单击过滤、再点当前 chip 或点「全部」取消
- 与搜索框**叠加过滤**（AND 关系）
- 只显示当前扫描结果中**实际存在**的分类（拖单个文件夹时不会铺 8 个空 chip）
- 分类过滤激活时底部计数显示「分类 X · N 组 / 共 M 组」

### 3.2 特效预览（复用现有 A/B 区）

特效映射为**虚拟方向 + 前缀动作**：

- 方向按钮区显示单个「特效」方向；动作按钮区显示帧序列前缀（如 `changrao`）
- A 区网格 / B 区动画播放 / 并集 bbox 裁剪 / 调速逐帧全部复用现有逻辑
- 缺漏检测：**不做**方向/动作查漏（无红按钮），只做**帧号断档检测**
  （`changrao_1~20` 中间缺号 → 红点 + 状态栏警告）

## 4. 模板配置（templates/default.json 新增字段）

```json
"categories": [
  {"name": "坐骑", "part_any": ["ride_front", "ride_back"]},
  {"name": "翅膀", "part_any": ["wings"]},
  {"name": "特效", "id_prefix": ["50105"], "flat": true,
   "frame_pattern": "^(.+?)_(\\d+)$", "virtual_direction": "特效"},
  {"name": "主角", "id_prefix": ["501"]},
  {"name": "伙伴", "id_prefix": ["502"]},
  {"name": "怪物", "id_prefix": ["503"]},
  {"name": "BOSS", "id_prefix": ["504"]},
  {"name": "NPC", "id_prefix": ["505"]}
]
```

- `part_any`：组内任一部件名命中 → 该分类
- `id_prefix`：资源 ID 前缀命中 → 该分类
- `flat: true`：该分类为扁平结构（无方向/动作层级）
- `frame_pattern`：扁平帧名模式，匹配 `文件名去扩展名`（stem），
  group(1)=序列前缀（映射为动作名），group(2)=帧号；扩展名走模板 `extensions`
- `virtual_direction`：扁平资源在按钮矩阵中的虚拟方向名，默认「特效」

模板编辑器暂不管理 `categories`（直接改 JSON），后续按需加。

## 5. 实现要点

| 模块 | 改动 |
|------|------|
| `core/template.py` | 新增 `categories` 字段 + `classify()` / `flat_rule()` / `category_names()` |
| `core/scanner.py` | `PartData.is_flat`；`scan_part` matrix 为空且纯 ID 时尝试扁平扫描；`_find_part_folders` 收集扁平文件夹；`IdGroup.category` 分组时标注；扁平组跳过方向/动作查漏 |
| `ui/part_list.py` | 过滤框下方 FlowLayout chips 行；分类过滤与文字过滤叠加；计数反馈 |
| `ui/button_matrix.py` | `show_part`/`show_group` 对 `is_flat` 特殊处理：方向/动作按钮来自实际数据而非模板列表 |
| `app.py` | 传递模板给 PartList（chips 来源）；状态栏帧号区间对扁平资源不补零显示 |

扁平扫描入口顺序：名字解析命中纯 ID → 常规方向结构扫描失败（matrix 空）→
查模板 flat 规则（ID 前缀命中）→ 按 stem 正则分组帧 → 虚拟方向矩阵。
带 `_part` 后缀的文件夹不做扁平兜底（防止误判）。

## 6. 测试要点与结果

测试文件：`tests/test_m21_category_flat.py`（核心扫描）、`tests/test_m21_gui_chips_fx.py`
（chips/按钮矩阵）、`tests/test_m21_e2e_realdir.py`（真实目录端到端）。

- ✅ 扁平特效：单拖 `50105101` 可扫描（changrao 20 帧连续）、A/B 区可预览、
  删帧后断档检测报红（gaps=[4]）
- ✅ 分类：真实父级目录 190 组全部分类正确——
  主角 30 / 伙伴 41 / 怪物 77 / BOSS 12 / NPC 25 / 坐骑 3 / 翅膀 1 / 特效 1
  （坐骑/翅膀按部件优先于 ID 前缀、7 位怪物变种 5030421 归怪物）
- ✅ chips：过滤（主角 2/4 组）、再点取消、与搜索叠加（AND）、
  分类 <2 时自动隐藏 chips 行；计数栏显示 `分类 · N/M 组`
- ✅ 特效选中后按钮矩阵显示 虚拟方向「特效」+ 动作「changrao」；
  状态栏帧号区间 `1–20`（不补零）；A 区帧名显示真实文件名
- ✅ 回归：全部既有测试（smoke_*、m7–m19、layertoggle）通过；
  带 `_part` 后缀的文件夹不误判为特效
- ⚠️ 已知环境问题（非本模块引入）：offscreen 模式下加载大量真实图片后进程
  退出阶段偶发 0xC0000409 崩溃（main 基线同样复现），功能输出完整不受影响
