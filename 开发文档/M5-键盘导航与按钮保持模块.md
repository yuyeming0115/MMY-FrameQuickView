# M5 · 键盘导航与按钮保持模块

> 状态：**已合并（PR #5）** · 2026-08-19 · 基于 v0.3 定稿的交互优化里程碑
> 2026-09-28 新增功能 3（M33）：切换部件/角色ID 保持方向动作（PR 待合并）

## 一、需求背景

实测反馈（2026-08-19）：
1. 切换方向时当前动作被重置，无法快速跨方向比对同一动作
2. 希望 B 区支持键盘操作：**←/→ 切方向，↑/↓ 切动作**，替代逐次点击按钮

## 二、功能 1：方向/动作切换互相保持

### 根因

`MainWindow._on_direction_selected` 调用 `_update_matrix(direction, None)`，**动作参数硬编码为 `None`**，导致每次切换方向后动作被重置为「第一个可用动作」。

### 修复

```python
def _on_direction_selected(self, direction: str) -> None:
    # 切换方向时保持当前动作（该动作在新方向缺失时由 show_part/show_group 兜底）
    _, action = self.matrix.current()
    self._update_matrix(direction, action)
    self._after_matrix_change()
```

- `_on_action_selected` 原本就保持方向（`direction, _ = self.matrix.current()`），无需修改
- **兜底逻辑保留**：若保持的动作在新方向下缺失（`missing_actions` 命中），`show_part`/`show_group` 自动跳到该方向第一个可用动作，并在按钮上以红色缺失样式提示

## 三、功能 2：B 区键盘导航

### 实现位置

`MainWindow.keyPressEvent`（窗口级事件，按钮点击后焦点自然落在按钮上，按键可被捕获）。

### 按键映射

| 按键 | 行为 | 范围 |
|------|------|------|
| `←` | 方向后退一格 | `tpl.directions` 循环 |
| `→` | 方向前进一格 | `tpl.directions` 循环 |
| `↑` | 动作后退一格 | `tpl.actions` 循环 |
| `↓` | 动作前进一格 | `tpl.actions` 循环 |

- 走与鼠标点击**完全相同的信号路径**（`_on_direction_selected` / `_on_action_selected`），缺失组合的兜底行为与鼠标一致
- 有数据才响应：未选中部件/组或模板为空时不拦截
- **输入控件保护**：焦点在 `QLineEdit`（左栏过滤框）或 `QComboBox`（模板下拉）时不拦截方向键，避免干扰文字编辑/下拉选择；按钮聚焦时正常生效

## 六、功能 3（M33）：切换部件/角色ID 保持方向动作（2026-09-28）

### 需求

用户反馈：在 B 区选了某个方向 + 动作后，切换角色 ID（部件/套装组）时这两个选择被重置回默认 SE+idle，跨 ID 比对同一动作需反复重选。期望：**保持方向与动作，直到用户主动改变**。

### 根因

`MainWindow._on_part_selected` / `_on_group_selected` 调用 `_update_matrix(None, None)`，按钮矩阵每次都走「首次进入」默认逻辑（SE + 按类型默认动作）。

### 修复（src/app.py）

切换部件/组时携带 `matrix.current()` 继续传递（与 M24 自动重扫的保持现场同一模式）：

```python
direction, action = self.matrix.current()
self._update_matrix(direction, action)
```

### 附带修正（src/ui/button_matrix.py）：兜底条件「缺失」→「不可用」

保持的方向/动作在新部件不可用时必须回退默认，原判断有两个漏洞：

| 位置 | 原条件 | 问题 | 新条件 |
|------|--------|------|--------|
| `show_part` 方向 | `direction in miss_dirs` | 漏掉非模板方向（如特效虚拟方向「特效」切回常规部件）→ 矩阵无 checked，B 区无资源 | `direction not in avail` |
| `show_part` 动作 | `action in miss_acts` | 漏掉 unexpected（如把角色的 run 带进坐骑）→ 选中灰显且无资源的动作 | `action not in present` |
| `show_group` 方向 | `direction in miss_dirs` | 同上 | `direction not in avail_d` |
| `show_group` 动作 | `action in miss_acts` | 同上 | `action not in owned_a_dir` |

回退规则不变：方向回退第一个可用方向；动作按类型默认（`pick_default_action`：主角 idle、坐骑 ride_idle，缺失回退字母序第一个）。用户显式点按钮 / 键盘导航 / M24 自动重扫走的都是同一兜底，行为随之更合理（切到不含当前动作的方向时自动落到可用动作，而不是显示「无资源」）。

### 保持语义边界

- 保持的依据是按钮矩阵的选中态，用户点方向/动作按钮（或键盘导航）即自然改变，无额外状态
- 拖入新文件夹、模板切换、重启恢复选中：同样保持（新数据缺失时兜底回退）
- 测试目录结构注意：同父目录放 ≥2 个跨 ID 部件会触发 M23 套装合并——部件级测试须用同 ID 部件
