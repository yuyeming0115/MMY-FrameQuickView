# M3 · B 区动画播放模块

> 状态：✅ 已完成（2026-08-19）· 配套 PR #3
> 关联：开发文档/01-需求方案与UI设计-v0.3.md（第 3.3 节叠层、F6 棋盘格背景）

## 一、模块归属

| 文件 | 职责 |
|------|------|
| `src/ui/anim_view.py` | B 区 GIF 动画播放控件（播放/暂停/FPS/步进/循环/棋盘格） |
| `src/ui/worker.py` | 后台解码 worker（grid_view / anim_view 共用） |
| `src/ui/grid_view.py` | A 区点击某帧 → `frame_clicked(index)` |
| `src/app.py` | `_show_anim()` / `_on_grid_frame_clicked()` A/B 区联动调度 |

## 二、功能

- **自动同步**：切换方向/动作/部件/组时，B 区与 A 区同步加载同一组帧
- **播放控制**：播放/暂停、FPS 滑杆 1–60、上一帧/下一帧、循环开关
- **棋盘格背景**：默认透明融入 UI，勾选后显示棋盘格，方便检查 alpha 毛边
- **A→B 联动**：点击 A 区任意帧，B 区跳转并暂停，方便逐帧对照
- **100% 原尺寸、并集 bbox 对齐、无边框**，与 A 区一致

## 三、关键实现

### 3.1 共用后台解码 `DecodeWorker`

为避免 grid / anim 重复写 worker，M3 把解码逻辑抽到 `src/ui/worker.py`：

```python
DecodeWorker(layers: list[list[Path]])
  → frame_ready(idx, PIL.Image, label)
  → finished(total)
```

- 子线程只做 PIL 解码 + alpha 合成
- `QPixmap` 在主线程的 `_on_frame` 回调里创建（`QPixmap` 不可跨线程）

### 3.2 `AnimView` 状态机

| 状态 | 行为 |
|------|------|
| 无帧 | 画布空白，播放按钮不可用 |
| 解码中 | 标题显示「解码中…」，播放按钮未按下 |
| 解码完成 | 自动开始播放（循环默认开启），FPS=12 |
| 用户点击 A 区帧 | `goto_frame(idx)` → 暂停 → 显示该帧 |
| 点击上一帧/下一帧 | 暂停并移动一帧 |

### 3.3 棋盘格背景 `_AnimCanvas`

- 继承 `QLabel`，重写 `paintEvent`
- 未勾选棋盘格：先画透明背景，再居中画当前帧
- 勾选棋盘格：先填充 16×16 灰白相间方块，再居中画帧

### 3.4 方向/动作按钮迁移（M7）+ B 区控制条跨整行（M8）

**M7**：把方向/动作按钮从「B 区画布与控制栏之间（横向堆叠）」进一步迁移到 **B 区左侧边栏（纵向堆叠）**，方向 5 个一列、动作 9 个一列；画布独占右侧 stretch=1。

**M8 调整**：
- AnimView 外层改 QVBoxLayout：内嵌 QHBoxLayout（左按钮矩阵 \| 右 canvas）+ 底部整行控制条（QHBoxLayout），控制条不再与按钮矩阵共享底部空间
- 按钮 `min-height: 26px; max-height: 32px` 锁定高度（修「按钮被切断」问题：B 区高度不够时 layout 反向压缩按钮导致文字被截断）
- `ButtonStack` 不再带 stretch 因子，高度由按钮组 sizeHint 决定

### 3.5 显向 + 8方向热区 + 拖拽旋转（M8）

用户在 mockup 中提出：B 区画布上叠加 8 个方向热区（半透明虚线框 + 方向文字），点击=方向切换；按住拖拽转一圈模拟 idle 旋转。用户拍板"沉浸式"：**仅 hover / 拖拽时才显示，离开画布后全部隐藏**。

实现：
- `_AnimCanvas` 增加 `direction_overlay_clicked(direction)` 信号、`set_dir_overlay_enabled/set_available_dirs/set_current_dir` API
- 3x3 网格槽位映射（`OVERLAY_SLOTS`，中心 (1,1) 留空放动画），`_slot_dir_at(pos)` 鼠标位置→方向
- 角度→方向映射（`ANGLE_TO_DIR`，atan2(dy,dx) 屏幕 y 向下：0°=E、90°=S、180°=W、270°=N），按 45° 分桶
- mousePressEvent 记起点、mouseMoveEvent 算角度差切方向（>6px 防抖）、mouseReleaseEvent 区分点击（<8px）/拖拽
- 点击/拖拽只对 `available_dirs`（=当前 tpl.directions）响应，不在的方向灰显不可点
- `ButtonStack` 增加 `header_btn_text` 参数，`ButtonMatrix` 在「方向」组顶部放「显向」toggle 按钮，信号 `overlay_toggled(bool)`
- app.py 接线：`matrix.overlay_toggled → anim_view.set_dir_overlay_enabled`；`anim_view.direction_overlay_clicked → _on_direction_selected`；`_after_matrix_change` 同步 `set_current_dir`；模板切换同步 `set_available_dirs`

### 3.5 A/B 联动

`app.py` 中：

```python
self.grid_view.frame_clicked.connect(self._on_grid_frame_clicked)

def _on_grid_frame_clicked(self, idx: int) -> None:
    self.anim_view.goto_frame(idx)

def _after_matrix_change(self) -> None:
    self._show_grid()
    self._show_anim()
    self._refresh_status()
```

`_layers_for_current()` 统一计算当前 (组/部件) + (方向,动作) 的帧序列，A/B 区共享，避免两边解码结果不一致。

### 3.6 切换体验优化：延迟清空 + 整体替换（M6）

**问题**：原 `show_sequence` 切换瞬间即 `set_frame(None)` 清空画布，视觉上「关掉重新刷新」，解码期间闪黑。

**修复**：

- 切换时**保留旧动画继续播放**，标题显示「解码中…」
- 新序列在后台 `_pending_frames` 收集，**全部解码完成**后一次性替换 `_frames` 并自动播放
- `sender()` 竞态防护：旧 worker 残留的 queued 信号在新序列解码时被忽略，避免串帧

```python
def _on_frame(self, idx, img, label):
    if self._worker is None or self.sender() is not self._worker:
        return  # 旧 worker 残留信号丢弃
    self._pending_frames.append(_img_to_pixmap(img))
    ...
```

### 3.7 按钮矩阵布局塌缩修复（M9）

**症状**：方向/动作按钮区只剩 header（`方向 ⇆ 显向` + 第一个动作 `idle`），下面所有按钮被压扁到每个 ~3px，纵向堆在一起；唯一可见的 `idle` 按钮宽度也仅 90px 而 viewport 88px，右边被裁 10px。

**根因**：`ButtonStack` 内部 `addStretch(1)` + 外层 `QSizePolicy.Preferred` 让 ButtonStack 的 minimumSize_hint 反馈给 layout 时为 0；
ButtonMatrix.layout 拿到的 dir_stack/act_stack 实测 height = ~22px（stretch 把 layout 撑没），而 sizeHint 真正算的是 230/393 → 巨大不一致。
最终 matrix 实测 49px（被压成 layout 默认），但 sizeHint 629 → viewport 给我 621 → 滚动条滚不上、内容全糊。

**修复**：

1. `ButtonStack._layout` 去掉 `addStretch(1)`，让 layout 按内容算 height
2. `rebuild` 清空循环改成 `while self._layout.count() > 0`（之前 `> 1` 会漏清旧 stretch）
3. `_MatrixScrollArea` 改回 `setWidgetResizable(True)`，让 widget 自动 fill viewport
4. `BTN_STYLE`：`max-width: 16777215`、`min-width: 0`、缩 padding 到 3px 8px，让按钮自适应 viewport 宽度而不是被 max-width:88 卡住

**验证**：

```

matrix sizeHint: 545
vbar visible: False       ← sizeHint < viewport，无需滚动
方向按钮 y=6,56,106,156,206 (5 个，80x40，完整)
动作按钮 y=0..288 (9 个，80x32，完整)
```

### 3.9 左栏宽度 splitter 可拖 + 树列宽跟随容器（M10）

之前 `PartList.setFixedWidth(220)` 锁死左栏，导致 `50142004 · 月河郡主(琴)·发` 这种 ID+中文长条目出省略号。改成 `setMinimumWidth(220) + setMaximumWidth(480)` + `resizeEvent` 同步树内第 0 列宽 = `容器宽 - 40`（折叠按钮 28 + padding 12）：

```python
# src/ui/part_list.py
LIST_COL_MIN_WIDTH = 160        # 列宽下限（防止 splitter 拖太小时列被压到 0）
LIST_COL_PADDING = 40           # 容器宽 - 折叠按钮 28 - 内边距 12

self.setMinimumWidth(220)
self.setMaximumWidth(480)

def resizeEvent(self, event):
    super().resizeEvent(event)
    new_w = max(LIST_COL_MIN_WIDTH, self.width() - LIST_COL_PADDING)
    header = self.tree.header()
    if header.sectionSize(0) != new_w:
        header.resizeSection(0, new_w)
```

`splitter.setSizes([220, 1060])` 保留作初始比例。`tests/test_m10_left_resize.py` 验证：

```

[2] initial left pane width = 220
[3] tree col 0 initial = 180
[4] after setSizes([320,...]): pl.width=320, col0=280
[5] after setSizes([480,...]): pl.width=480, col0=440
[6] after setSizes([100,...]): pl.width=220 (min 生效)
[7] after setSizes([600,...]): pl.width=480 (max 生效)
[8] longest label = "501420004 · 月河郡主(琴)·发" (~294px)  → pl=480 时 col0=440 装得下
```

用户操作：拖 splitter 手柄即可自由调整左栏宽度（220~480）。最长条目（21 字符 ≈ 294px）在 320 以上宽度能完整显示。

### 3.10 左栏「📖 选择匹配表」按钮 + BTN_STYLE max-width 警告修复（M10.1）

**问题 1：`QWidget::setMaximumSize: (/QPushButton) The largest allowed size is (16777215,16777215)` 警告 ×6**
根因：`button_matrix.BTN_STYLE` 里 `max-width: 16777215`（Qt 的 `QWIDGETSIZE_MAX` 魔法数字）。Qt 把 QSS 的 `max-width` 解析为 `setMaximumWidth(16777215)`，边界值触发 `setMaximumSize` 警告。按钮宽度已由 `_MatrixScrollArea.resizeEvent` 的 `setFixedWidth(viewport().width())` 控制（M9 确认），无需 QSS 再来一层 max-width。修复：删掉 `max-width: 16777215`，保留 `min-width: 0`（让按钮自适应视口不被默认最小宽撑开）。offscreen 下不触发，真实平台 show 后触发，故之前测试未察觉。

**问题 2：左栏中文名又消失**
根因：自动发现 + QSettings 持久化在「拖入目录不在匹配表父树 + 之前持久化路径失效」时双双失败 → 弹窗分支（`_setup_namemap` 第 196-206 行）。顶部「文件 → 选择匹配表文件…」菜单藏得深，用户易错过。
修复：在 PartList 过滤框旁（与 ▼ 折叠按钮并排）加显式「📖」按钮，`pick_namemap` 信号 → `app._pick_map_file` 打开 `QFileDialog` 选 txt，选完 `_reload_namemap(path)` 刷新左栏并持久化到 QSettings。用户随时主动选，不依赖自动发现/弹窗。

```python
# src/ui/part_list.py
class PartList(QFrame):
    pick_namemap = Signal()          # 点击「📖」触发，app 打开文件选择

    # filter_row 中
    self.map_btn = QPushButton("📖")
    self.map_btn.setFixedWidth(28)
    self.map_btn.setToolTip("选择 ID-中文名匹配表（手动指定 txt）")
    self.map_btn.clicked.connect(lambda: self.pick_namemap.emit())
```

## 3.11 多级目录递归扫描 + 左栏默认折叠 + 后台解码防崩（M11）

**背景**：用户目录 `E:\Temp\新ID` 是三级结构 `根 / 角色名文件夹 / 部件文件夹 / 方向 / 动作 / 帧.png`（如 `新ID\逍遥仙(扇)\501031003_shadow\E\idle\0001.png`）。原 `scan_root` 只扫一层，把「角色名文件夹」当部件解析 → 全部 ignored，拖 `新ID` 实际啥都没扫到；且早期把 `角色/部件` 错拼成 `根/部件`，后台解码时帧路径缺了角色层 → `FileNotFoundError` 让 QThread 崩溃。

**改动**：
1. `src/core/scanner.py`：`scan_root` 改为 **BFS 递归**（`_find_part_folders`，`max_depth=4`）找任意深度的部件文件夹。`scan_part` 一律用**真实完整路径**调用 → phantom 路径彻底消失。三种拖入都正确：
   - 拖 `新ID`（根）→ 递归找全部 角色/部件；
   - 拖 `拓跋影(双刀)`（角色文件夹）→ 找其下部件；
   - 拖单部件文件夹 → 单部件（root 记父目录）。
   部件文件夹命中后**不再下钻**（其下是 方向/动作）。
2. `src/ui/part_list.py`：左树**默认折叠** —— `_rebuild` 中 `grp_item.setExpanded(False)`，折叠按钮初始 `▶`、`_all_expanded=False`。点 ▼ 展开。
3. `src/core/imageops.py` + `src/ui/worker.py`：**防御缺失帧**。`sequence_union_bbox` 对不存在/损坏的帧 `try/except` 跳过返回 `None`；`DecodeWorker.run` 先筛掉磁盘不存在的路径、打印告警（`[DecodeWorker] 跳过 N 个不存在的帧文件…`）再解码，缺失时安全 `finished.emit(0)`，不再崩溃。

**验证**：`tests/test_m11_multilevel_scan.py` 构造三级临时树，三种拖入模式断言分组正确 + 帧路径含真实角色层且无 phantom；`sequence_union_bbox` 缺文件单测不抛异常。smoke_core / m8 / m9 / m10 全部回归通过。

### 3.12 默认方向固定为 SE（M12）

**需求**：首次进入某部件/组（方向未指定，即 `direction=None`）时，默认高亮 **SE**（东南），而非原先的「第一个可用方向」。

**改动**：`src/ui/button_matrix.py`
- 新增模块常量 `DEFAULT_DIRECTION = "SE"`（文件顶部 import 后）。
- `show_part`（原 line 155）：把原来 `if direction is None or direction in miss_dirs: direction = avail[0]` 拆成两分支——`direction is None` 时优先 `DEFAULT_DIRECTION if DEFAULT_DIRECTION in avail else avail[0]`；`direction in miss_dirs` 时仍回退 `avail[0]`。
- `show_group`（原 line 190）：同理，`direction is None` 时优先 SE（在组可用方向并集内），否则回退 `sorted(avail_d)[0]`；`direction in miss_dirs` 时回退。
- 关键保护：**仅当该部件/组确实拥有 SE 时才默认选中**，否则回退到首个可用方向，避免强制高亮一个缺失方向。

**验证**：`tests/test_m12_default_direction.py`

[3] 组含 SE: 默认方向 = 'SE'           ✓

ALL M12 PASS
