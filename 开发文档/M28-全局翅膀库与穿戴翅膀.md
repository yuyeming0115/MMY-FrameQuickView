# M28 - 全局翅膀库与穿戴翅膀

> 状态：开发中　|　分支：`feature-fx-library`　|　日期：2026-08-29

## 需求背景

M26 把「特效」做成了全局可穿戴库（放最外层文件夹，预览任意套装时挑一个穿上）。
用户随即提出：**翅膀也是通用资源**，能不能同样处理？

> 「特效是通用资源，所有主角都可以穿戴……那按照你的思路，「翅膀」也可以单独
> 放到一个文件夹里？穿戴翅膀也是这样实现？」

答案是可以，但**取帧方式不同**——这是 M28 与 M26 唯一的本质差异：

| | 特效（M26） | 翅膀（M28） |
|---|---|---|
| 目录结构 | **扁平**：图片直接在根目录，无方向/动作层级 | **常规**：`{方向}/{动作}/0001.png` |
| 识别方式 | 模板 `categories.flat` 规则（`id_prefix: 50105`） | 部位后缀 `_wings` |
| 取帧 | 取自身唯一序列（虚拟方向「特效」） | **按当前 (方向, 动作) 取帧** |
| 对齐 | 需居中 + **需要偏移微调** | 需居中，但**方向动作本就对齐 → 不提供微调** |
| 叠加位置 | 置顶最上层 | 角色之上、特效之下 |

### 附带修复：单一部位的素材库被误判成「套装」

做 M28 时发现一个连带问题：M23 的套装判定是「同父文件夹 ≥2 部件、跨 ≥2 ID、
同一资源类别」。把 8 个翅膀放进 `翅膀库/` 后，它们**全是 wings、全是「翅膀」类别**
→ 满足条件 → 被合并成一个「翅膀库」套装组，预览时 8 对翅膀全叠在一起。

**修复**：套装判定时追加「至少 2 种不同部位」——真套装必然含 body/hair/weapon/
shadow 等多种部位；全是 wings（或全是 shadow）的文件夹是**素材库**，不是套装，
应各自按 ID 独立成组。

```python
part_types = {p[1] for p in (tpl.parse_folder_name(c.name) for c in leaves) if p and p[1]}
if (... and len(part_types) >= 2):     # 新增
```

> 纯 ID 文件夹（`part=None`，如 `505026`）不参与部位多样性判定，避免误伤既有行为。

## 设计方案

### 1. 扫描层：全局翅膀库

`ScanResult` 新增 `wing_library: list[PartData]`——**所有** `part == "wings"` 的部件，
无论物理位置（套装目录内 / 最外层独立文件夹 / 任何深度），统一收进全局库。

```python
result.wing_library = [p for p in result.parts if p.part == "wings"]
```

与 `fx_library` 并列，两套库互不干扰。

### 2. UI：显示层面板加「穿戴翅膀」下拉框

复用 M26 的穿戴行组件（重构为 `add_wear_row(caption, handler)` 工厂），
「显示层」面板下出现两行：

```
显示层
穿戴特效   [ 无 ▾ ]
穿戴翅膀   [ 无 ▾ ]
☐ 身体 ☑ 头发 ☑ 武器 …
```

- 选项：`无` + 翅膀库全部翅膀（显示名 = 匹配表中文名 + `·翅膀`，无映射兜底文件夹名）
- 无对应库 / 单部件视图 → 该行自动隐藏（面板高度由 `wear_selector_count` 动态计算）
- 选择后发出 `wing_dressed(key)` 信号，`""` 表示不穿戴

### 3. 状态：按组记忆穿戴选择

- `self._dressed_wings: dict[str, str]` = {组 key: 翅膀 key}
- QSettings：`layering/dressed_wings/{group_key}`（`""` = 不穿戴）
- 切换组时自动恢复；**所有组**（套装组 + 同 ID 角色组）都能穿

### 4. 合成：穿戴翅膀追加为顶层 flat 层

抽出公共方法 `_append_dressed_part()`，M26/M28 共用：

```python
def _append_dressed_part(self, layers, flat_mask, fx_offsets, part_keys,
                         dress_key, by_key) -> int | None:
    p = by_key.get(dress_key)
    if p is None: return None
    if any(q.name == p.name for q in self._group.parts): return None   # 不重复叠加
    if p.is_flat:
        ad = next((a for col in p.matrix.values() for a in col.values()), None)
    else:
        ad = p.action_data(direction, action) \      # 翅膀：按 (方向,动作) 取帧
             or next((a for col in p.matrix.values() for a in col.values()), None)
    ...
    flat_mask.append(True)      # 独立资源 → 一律按 bbox 居中对齐
    return idx
```

层顺序：`组内部件 → 穿戴翅膀 → 穿戴特效`（特效永远最顶）。

### 5. 关键：区分「真正的特效层」与「穿戴的翅膀」

穿戴的翅膀 `flat_mask` 也是 `True`（独立资源需要居中），但**不需要偏移微调**。
若沿用 M26 的「第一个 flat 层即可微调」逻辑，Ctrl+方向键会误调翅膀。

**方案**：`_layers_for_current` 顺带产出 `self._fx_layer_indices`（真正的特效层下标集），
`AnimView.set_fx_layer_indices()` 告知画布，`keyPressEvent` 优先取 `min(该集合)`：

```python
fx_idx = min(self._fx_layer_indices) if self._fx_layer_indices else None
if fx_idx is None:      # 兜底：退化到「第一个 flat 层」
    fx_idx = next((i for i, f in enumerate(self._flat_mask) if f), None)
```

`_fx_layer_indices` 只包含：组内 flat 部件 + 穿戴的特效；**不含**穿戴的翅膀。
单部件视图下若自身是特效 → `{0}`。

> 为什么用下标集而不是 flag 列表：`flat_mask` 语义是「需居中对齐」，
> 而微调语义是「需要人工纠偏」，两者正交，硬塞进一个字段会互相污染。

## 兼容性

| 场景 | 行为 |
|------|------|
| 翅膀仍在套装目录内（未迁移） | 组内已有 → 穿戴下拉框选它时**不重复叠加** |
| 翅膀已移到外层 `翅膀库/` | 各自按 ID 独立成组（不再被合并成假套装），供任意组穿戴 |
| 单部件视图 | 穿戴行隐藏，行为同现状 |
| 无翅膀资源 | 「穿戴翅膀」行不显示，面板高度自动收缩 |
| 翅膀 + 特效同穿 | 翅膀在角色之上、特效置顶；Ctrl+方向键只调特效 |

## 测试点

1. 翅膀放最外层独立文件夹 → 进全局库，下拉框可见
2. 翅膀库**不**被合并成套装，各翅膀按 ID 独立成组
3. 穿戴翅膀 → 追加为顶层 flat 层
4. 切换动作（idle ↔ run）→ 翅膀帧数随 (方向,动作) 变化，而非固定取首序列
5. 只穿翅膀时 `_fx_layer_indices` 为空 → Ctrl+方向键不会误调翅膀
6. 翅膀 + 特效同穿 → 特效置顶末位，只有它可微调
7. 翅膀已在本组内 → 不重复叠加
8. 穿戴选择按组 key 记忆，切回自动恢复
