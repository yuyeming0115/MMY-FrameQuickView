## Bug 修复：默认播放动画不是 idle（坐骑影子/整组落空为 None）

- **现象**：打开坐骑类资源时，ride_front/ride_back 部件正确默认 ride_idle，但坐骑的
  shadow 部件（及整组）默认动作变成 `None` → B 区不播放任何动画。用户报告"默认播放不是 idle"。
- **根因**：`button_matrix.pick_default_action` 仅用 `约定动作 ∩ 实际拥有` 作为候选。
  坐骑影子（如 `50302301_shadow`）只有 `ride_idle/ride_run`，而 `eff_type` 被判定为
  `non_protagonist`（影子 `part_type=""` 取角色类型，503 前缀→non_protagonist），
  约定动作 `[idle,run,attack...]` 一个都不中 → 候选为空 → 返回 `None`。
- **修复**：`pick_default_action` 增加 `all_avail` 参数（部件实际拥有的全部动作）；
  当 `约定∩实际` 为空但部件确有动作时，回退到实际动作，坐骑影子正确落到 `ride_idle`。
  两处调用（`show_part` / `show_group`）同步传入 `sorted(present)` / `sorted(owned_a_dir)`。
- **验证**：真实目录 `E:/XYJProject/美术资源/动画序列帧/角色输出图` 扫描 213 部件，
  修复前 5 个条目（3 个 shadow + 1 个 flat）默认动作为 None；修复后坐骑影子→ride_idle。
  普通主角 body 仍 idle（无回归）。`tests/test_m27_default_action.py` 新增第 9 例回归，
  M27 / M12 全过。
- 文件改动：`src/ui/button_matrix.py`、`tests/test_m27_default_action.py`。已提交 `8bc8a3c` 并推送。

## Bug 修复：重启恢复选中后方向/动作按钮点击无反应（M29）

- **现象**：有时启动应用恢复了上次资源、显示 idle 动画，但点 attack/skill 没反应，
  必须再点一次左栏子项按钮才恢复。
- **根因**：`app._on_folder_dropped` 的时序错误——`load_result` 自动选中第一项（触发
  `part_selected` 信号设置 `_part`）、`_select_by_key(saved_sel)` 恢复上次选中之后，
  才执行 `self._group = None; self._part = None`，把刚建立的选中状态抹掉。
  之后点按钮走 `_update_matrix`，`_part/_group` 均为 None → 直接跳过无反应。
- **附带 Qt 坑**：`QTreeWidget.setCurrentItem` 对「已选中项」不触发
  `itemSelectionChanged`，因此恢复目标与自动选中的第一项相同时不会二次触发信号。
- **修复**：把 `self._group = None; self._part = None` 挪到 `load_result` **之前**
  （清旧状态 → 重建列表自动选中并设置 `_part` → 恢复记忆选中项）。
- **验证**：`tests/test_m29_restore_selection.py` 四场景全过（首次启动 / 恢复第一项 /
  恢复第二项 / 恢复组头 GRP:），M27 / M12 回归无破坏。
- **测试脚本坑**：offscreen 测试里 `QSettings()` 无参构造与
  `QSettings("MMY","FrameQuickView")` 不是同一存储（QApplication 未设组织名/应用名），
  写入读不到——测试必须用与 MainWindow 相同的显式构造。
- 文件改动：`src/app.py`、`tests/test_m29_restore_selection.py`（新增）。已提交 `4d61604` 并推送。

## Fork 显示「main 有 11 个未推送」排查

- **真相：远端与本地完全一致**。`gh api` 查远端 main = `4d61604` = 本地 main，
  `git log origin/main..main` 为空（领先0/落后0）；本地 `feature-m7-m12-wip`
  也与远端同名分支同为 `1314583`（无上游但内容一致）。
- **原因**：Fork 读的是本地 `.git/refs/remotes/origin/main`，该 ref 曾被沙箱 overlay
  回滚到旧值 `eca0ada`（main 第 12 条提交，2026-08-29），于是把其后的 11 条算成「未推送」。
- **解法**：非沙箱下 `git fetch origin main` 刷新 `origin/main`，Fork 里点 Fetch /
  重启后即显示 0。教训：怀疑远端不同步时用 `gh api` 查远端真相，不要只信本地 ref。
