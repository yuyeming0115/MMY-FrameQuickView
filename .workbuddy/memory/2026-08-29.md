## Bug 修复 + 新功能：叠层播放（多轮迭代至 v7）

### 问题1：短序列帧消失 → 循环播放
- 取模 `i % len(layer)`，各层独立循环

### 问题2：层间对齐 + 居中（v1→v7 迭代）
- v1: 全部居中 → 部件错位
- v2: 特效居中全画布中心 → 特效跑偏
- v3: 特效居中非特效锚点 → 角色偏移+裁边
- v4: composite_layers 内加 shift → 全白失败（**坐标系混用 bug**：cx 是画布坐标，anchor_cx 是图像绝对坐标，直接相减得 nonsense）
- v5: bbox 只用非特效层 → 对齐OK但特效被裁切
- v6: bbox 用全部层 + 逐帧算 anchor → 对齐+不裁切，但**逐帧抖动**
- v7: 跨帧 anchor + bbox缓存 + 防抖 → **角色稳了**，但**特效还在抖**
- **v8 最终方案（当前）** —— 特效层也用固定锚点：
  1. **普通层跨帧 anchor**（v7）：所有帧共用同一 shift
  2. **特效层 layer_union**（v8 新增）：{层索引: 该层跨帧并集 bbox}，
     特效整体居中 + 帧间保留原始相对位移。
     ⚠ 根因：特效每帧 bbox 尺寸不同，逐帧 `im.size` 居中 → 每帧基准漂移 → 抖动
  3. **bbox 缓存**：每文件只开一次，O(帧×层) → O(总文件)
  4. **防抖刷新**：Ctrl+方向键 180ms 防抖

### 核心教训（可复用，重要）
- **动画序列的居中偏移必须跨帧固定**——任何"逐帧计算 bbox 再居中"的方案都会抖动，
  因为动画各帧轮廓大小天然不同。正确做法：算一次全序列并集 bbox 作锚点，
  每帧 = 锚点基准 + 该帧在序列内的相对位移。
  这个坑在角色层和特效层各踩了一次（v6 和 v7）。
- **图像批处理要预计算缓存 bbox**，避免 N帧×M层 的重复文件 IO
- **交互微调必须防抖**，否则每次输入触发全量重解码

### UI 调整
- 「显示层」toggle 面板移到右上角（y=4）
- Ctrl+方向键微调特效偏移（5px/次），QSettings 持久化

## M26 新功能：全局特效库与套装穿戴（分支 feature-fx-library）

### 需求
特效是通用资源（所有主角可穿戴），原本必须复制到每个套装目录（M25 按物理位置
归属）。改为：特效放最外层独立文件夹 → 全局特效库 → 任意套装手动"穿戴"。

### 方案
- `scanner.py`：`ScanResult` 新增 `fx_library`，收集**所有** is_flat 特效（无论
  物理位置）。无需新增目录约定——靠模板 `categories.flat` 规则自动识别。
- `anim_view.py`：`PartToggles` 加「穿戴特效」下拉框（无 + 特效库列表）与
  `fx_dressed` 信号；面板尺寸计算纳入下拉框；`set_fx_library()` 注入。
- `app.py`：
  - `_dressed_fx: dict[套装key, 特效key]` + QSettings（`layering/dressed_fx/`）
  - `_layers_for_current` 改返回 **4 元组**（+ part_keys），穿戴特效追加为顶层
    flat 层；`_append_dressed_fx` 去重（特效已在组内则跳过）
  - **part_keys 由合成链统一产出**是刻意的：避免调用方与合成链各算一份导致
    顺序错位（偏移微调会作用到错误的层）

### 兼容性
- 特效仍在套装目录内 → M25 自动并入照常；手动选它时检测到已在组内则不重复追加
- 单部件视图 → 下拉框隐藏

### 关键设计：偏移按"特效名"存取
→ 同一特效调一次偏移，所有套装复用，契合"通用资源"语义。

### 验证
- `tests/test_m26_fx_library.py` 6 项全过；全量回归 22 个脚本全过
- 顺带修复既有测试不稳定：`_layers_for_current` 改 4 元组后同步 3 个测试解包；
  test_m25/M26 加 `_hidden_parts = set()` 隔离用户本机 QSettings 残留
  （**教训：GUI 测试会读真实 QSettings，断言前必须先清理历史状态**）

## M27：默认播放动作按类型优化（idle / ride_idle）

- **根因**：`button_matrix.py` 的 show_part/show_group 用 `sorted(可用动作)[0]` 选默认动作。
  主角 E 方向约定动作是 `[idle, attack, run, ride_idle, ride_run]`，
  字母序第一个是 **attack** → 打开就播攻击动画。
- **修复**：新增 `pick_default_action(eff_type, avail)`，按类型优先：
  - 常规类型（主角/伙伴/怪物/BOSS/NPC/翅膀）→ `idle`
  - 坐骑（`mount`）→ `ride_idle`
  - 优先动作缺失 → 回退字母序第一个（保持鲁棒）
- 常量：`DEFAULT_ACTION = "idle"`、`DEFAULT_ACTION_BY_TYPE = {"mount": "ride_idle"}`
- 测试：`tests/test_m27_default_action.py` 8 项全过；关键回归全过

### 翅膀穿戴可行性（已分析，待用户决定是否实现）
翅膀是**常规部件**（模板 categories 靠 `part_any: ["wings"]` 识别，非 flat），
与特效（flat 扁平结构）的关键差异：
- **取帧**：特效取自身序列（无视方向/动作）；翅膀需按当前 (方向,动作) 取帧
- **定位**：两者都是独立资源，坐标系与主角色不同 → 都需要**居中对齐**

实现只需改 `app.py._append_dressed_fx`：
- 取帧时判断 `is_flat`（flat→自身序列，常规→按 (d,a) 取）
- `flat_mask` 一律设 True（穿戴的资源都居中对齐）
→ **不需要改 composite_layers / worker**（flat_mask 在这两层只用于"定位方式"判断）
另需：翅膀库识别（`part == "wings"`）+ 第二个下拉框「穿戴翅膀」。
⚠ 待解：同时穿翅膀+特效时，Ctrl+方向键微调只作用于"第一个 flat 层"，
需设计多层穿戴时的微调目标选择。

## M28：全局翅膀库与穿戴翅膀（分支 feature-fx-library，已实现待 PR）

### 上面那个 ⚠ 的解法
`_fx_layer_indices: set[int]` = 真正的特效层下标集，由 `_layers_for_current`
顺带产出 → `AnimView.set_fx_layer_indices()` → `keyPressEvent` 取 `min(集合)`。
只含「组内 flat 部件 + 穿戴的特效」，**不含穿戴的翅膀**（翅膀 flat_mask 为 True
是为了居中，不是因为需要微调）。
> 教训：`flat_mask` 语义是「需居中对齐」，微调语义是「需要人工纠偏」，
> 两者正交，不能复用同一字段。

### 实现要点
- `scanner.py`：`ScanResult` 新增 `wing_library`（`part == "wings"`，无论物理位置）
- `anim_view.py`：穿戴行重构为 `add_wear_row(caption, handler)` 工厂，
  「穿戴特效/穿戴翅膀」两行；空库自动隐藏；面板高度用 `wear_selector_count` 动态算
- `app.py`：抽出公共 `_append_dressed_part()`，M26/M28 共用；
  层顺序 = 组内部件 → 穿戴翅膀 → 穿戴特效（特效永远最顶）
- QSettings `layering/dressed_wings/{组key}`，按组记忆

### 附带修复（重要，顺手做的）
M23 套装判定是「同父 ≥2 部件 + 跨 ≥2 ID + 同一资源类别」。
把 N 个翅膀放进 `翅膀库/` → 全是 wings、全是「翅膀」类别 → **被合并成一个假套装**，
预览时 N 对翅膀全叠一起。
→ 追加条件「**至少 2 种不同部位**」：真套装必含 body/hair/weapon/shadow 多种部位；
  全是 wings / 全是 shadow 的是**素材库**，应各自按 ID 独立成组。
  纯 ID 文件夹（`part=None`）不参与该判定，避免误伤。
⚠ 这条改动会影响所有套装识别，回归时重点看 `test_m23_outfit_group.py`。

### 验证
- `tests/test_m28_wing_library.py` 7 项全过；全量回归 22 个脚本全过
- **回归踩坑**：串行跑全套时部分脚本（m7/m8/m9/m10_1/m10_left_resize）偶发失败，
  单独跑同一脚本却全过 → 根因是**测试间共享 QSettings 状态**（前一个脚本清掉了
  `last_map_file` 等）。已用 HEAD（M27）版本同口径对照，失败集合一致，与改动无关。
  → **教训：判断回归是否引入问题时，必须用「同口径对照」（同顺序跑基线），
    不能只看单脚本结果。** 对照方法：`git show HEAD:<file> > <file>` 还原（只读
    命令不写 .git），跑完再拷回备份。
